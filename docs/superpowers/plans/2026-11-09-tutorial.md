# 튜토리얼 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 처음 하는 사람이 원 잡기 → 콤보 → 피버 → 견제를 목표를 해내며 익히는 서버 튜토리얼 방을 만든다.

**Architecture:** 타임어택처럼 `Room` 생성자에 `tutorial` 플래그를 두고, 단계 정의·판정은 새 모듈 `server/src/tutorial.ts`가 맡는다. 튜토리얼 방은 평소 틱 대신 전용 틱(단계별 생성만)을 돌고, 단계가 바뀔 때 `game:sync`로 판을 비운다. 화면은 `tutorial:step` 이벤트로 안내 띠와 완료 창을 그린다.

**Tech Stack:** TypeScript, Socket.IO, Vite, `node --test` + tsx

**Spec:** `docs/superpowers/specs/2026-11-09-tutorial-design.md`

## Global Constraints

- 수치는 `shared/src/rules.ts`의 `RULES.tutorial`에만 둔다 (`CLAUDE.md`).
- 단계 순서 `own` → `combo` → `fever` → `steal`, 목표 own 3 · combo 5 · fever 1회 · steal 1, 피버 단계 시작 게이지 50, 단계 넘김 대기 1000ms.
- 튜토리얼 판에는 보스·아이템·증강·저주·이벤트·레이저·지도 패턴·무지개·황금 원이 없다. 판 시간 제한 없음. 결과 화면·기록 없음.
- 헛클릭은 감점·피버 감소 없이 콤보만 0.
- 사용자 지침: 테스트는 모든 기능을 구현한 뒤 한꺼번에 쓴다(Task 6). 그래서 이 계획은 과제마다 TDD를 하지 않는다.
- 커밋은 구현이 다 끝난 뒤 목적별로 나눈다(Task 8). 타입 검사·빌드 출력은 결과·오류 줄만 본다.
- 작업 브랜치: `main`에서 `feat/tutorial`.

## Review Focus

1. 튜토리얼 중 [건너뛰기]로 나가면 단계 넘김 타이머가 남아 빈 방에 이벤트를 보내지 않아야 한다 → Task 6 `나가면 단계 타이머가 정리됨`.
2. 같은 틱·같은 클릭에서 목표를 두 번 넘겨도(예: 3개째와 4개째) 단계가 한 번만 넘어가야 한다 → Task 6 `목표 달성은 한 번만 처리`.
3. 단계 넘김 대기(1초) 동안 원을 더 잡아도 다음 단계 진행 수에 섞이지 않아야 한다 → Task 6 같은 테스트에서 함께 확인.
4. 피버 단계에서 이미 피버 중이 아닌 상태로 시작해야 한다 (콤보 단계에서 우연히 피버가 켜져 있으면 끈다) → Task 6 `피버 단계 시작 게이지 50, 피버 꺼짐`.
5. 견제 단계의 봇 색 원을 잡아도 봇 점수가 음수가 되어 화면이 깨지지 않아야 한다 → Task 6 `견제 단계 봇은 원을 잡지 않음`에서 봇 점수 ≥ 0 확인.
