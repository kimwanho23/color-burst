# 협력전 우클릭 보호막 설계

2026-11-18. 상태: 구현 완료.

## 의도

협력전에서 탄막 사이에 끼었을 때 스스로 빠져나올 수 있는 비상 수단을 준다. 우클릭(모바일은 화면 버튼)으로 켜면 1.5초 동안 들어오는 공격을 모두 막는다. 판마다 쓸 수 있는 횟수가 정해져 있고, 쉬운 난이도일수록 많이 준다. 엑스퍼트는 0회로 쓸 수 없다. 내가 타이밍을 잘 잡아 위기를 넘겼다는 손맛이 핵심이다.

## 목표와 비목표

- 목표: 우클릭 한 번으로 1.5초 동안 피하는 공격의 피해를 모두 막는다(관통 대상은 동작 5번). 켜는 소리가 나고, 커서를 투명하고 연한 파란 구체가 감싼다.
- 목표: 판마다 사용 횟수 이지 3, 노말 2, 하드 1, 엑스퍼트 0.
- 목표: 모바일은 화면에 대체 버튼을 둔다.
- 목표: 지금 우클릭이 왼쪽 클릭처럼 원 잡기·수정 타격으로 처리되는 동작을 없앤다.
- 비목표: 방어막 아이템(`guard`, 3초 안에 한 번 막음)은 바꾸지 않는다. 대전 모드(협력전 외)에는 보호막을 넣지 않는다. 튜토리얼에는 넣지 않는다.
- 실패 기준: 켰는데 맞거나, 켠 사실이 나와 동료에게 잘 보이지 않거나, 우클릭이 여전히 원을 잡으면 실패다.

## 이름 (설계자 판단)

기존 코드의 `this.shield`·문서의 '보호막 단계'는 보스의 수정 구간을 뜻하고, 아이템은 '방어막'(`guard`)이다. 혼동을 피하려고 화면 이름은 사용자가 부른 대로 '보호막', 코드 키는 `barrier`로 한다. 이 문서에서 보스 쪽은 '수정 구간'이라고 부른다.

## 만드는 방법

| 안 | 내용 | 장단점 |
|---|---|---|
| A. 서버 판정 (선택) | 서버가 남은 횟수와 종료 시각을 갖고, 피해 계산 `damage()`에서 막는다 | 피해를 서버가 판정하므로 실제로 막히고 멀티플레이에서 모두 같은 상태를 본다. 일시정지·재접속을 기존 방식으로 처리한다 |
| B. 화면에서만 처리 | 클라이언트가 켜진 동안 피격 연출을 숨긴다 | 실제 피해는 서버가 주므로 막을 수 없다. 탈락했다 |

사용자가 A로 진행에 동의했다.

## 동작

1. **입력**
   - 게임 화면(`cv`)의 `pointerdown`에서 마우스 오른쪽 버튼(`e.button === 2`)은 클릭 판정으로 보내지 않는다. 모든 모드에서 우클릭은 원 잡기·수정 타격·빈 곳 클릭이 아니다.
   - `cv`의 `contextmenu`를 막아 브라우저 메뉴가 뜨지 않게 한다.
   - 협력전에서 우클릭은 `coop:barrier` 요청을 보낸다. 일시정지·시작 카운트다운 중에는 보내지 않는다(Space 스페셜과 같은 조건).
   - 모바일(터치)에서는 화면에 보호막 버튼을 둔다. 버튼에 남은 횟수를 표시하고, 0회가 되면 비활성으로 보인다. 위치·크기는 구현자 판단(엄지가 닿는 아래 구석, 게임 화면을 가리지 않게).
2. **사용 조건 (서버 확인)**: 협력전 진행 중, 사람(봇 아님), 탈락하지 않음, 접속 중, 기절 중 아님, 남은 횟수 1 이상, 이미 켜져 있지 않음. 하나라도 어긋나면 무시하고 횟수를 깎지 않는다. 수정 구간에도 쓸 수 있다.
3. **켜짐**: 남은 횟수를 1 줄이고 종료 시각을 `now + durationMs`로 정한다. 모두에게 플레이어 상태로 알린다.
4. **막기**: `damage()`에서 관통 대상(아래 5번)이 아니고 보호막이 켜져 있으면 아이템 방어막보다 먼저 막는다. 피해·기절·무적 부여 없이 `coop:hit`을 `blocked: true`로 보내고 `true`를 돌려준다. 그래서 막힌 공격의 처리는 아이템 방어막에 막혔을 때와 같다(예: 유도탄은 사라진다). 보호막이 켜져 있는 동안 아이템 방어막은 소모되지 않는다.
5. **관통**: 압살(`crush`), 분노(`rage`), 큰 구체 놓침(`threat`)은 보호막을 관통한다. 압살은 즉사 패턴의 긴장감을 지키기 위해서다(설계자 판단, 아이템 방어막과 같은 규칙). 분노와 큰 구체 놓침은 피하는 공격이 아니라 수정·큰 구체 처리에 실패한 벌칙이므로 관통한다(사용자 결정). 분노는 수정 구간 제한 시간으로 시각을 미리 알 수 있어 막을 수 있으면 보호막 한 번으로 벌칙이 사라지기 때문이다. 아이템 방어막의 기존 규칙(분노·큰 구체 놓침도 막음)은 바꾸지 않는다.
6. **꺼짐**: 종료 시각이 지나면 끝난다. 끝난 뒤 추가 무적은 없다. 판이 끝나면 지운다. 다음 판은 횟수를 새로 채운다.
7. **일시정지**: 남은 시간을 함께 민다(`guardUntil`과 같은 곳에서 `barrierUntil += delta`).
8. **재접속**: 남은 횟수와 종료 시각이 플레이어 상태에 실려 있어 그대로 이어진다.
9. **탈락**: 탈락하면 보호막은 의미가 없다. 별도 처리 없이 `damage()` 첫 줄의 탈락 검사가 먼저 걸린다.

## 화면과 소리

- **구체**: 내 커서를 투명하고 연한 파란 구체가 감싼다(테두리가 조금 더 진하고 안은 옅은 반투명). 자기가 켠 보호막만 자기 화면에서 보인다(사용자 결정). 게임은 각 화면에 자기 커서만 그리고 동료 커서 위치를 받지 않기 때문이다. 동료가 켰다는 별도 표시(피드·목록)도 두지 않는다. 동료가 보호막으로 공격을 막았을 때는 기존 피격 피드 한 줄만 '보호막으로 막음'으로 나온다.
- **남은 시간**: 끝나기 전 짧은 구간에 구체가 줄어들며 흐려진다. 정확한 연출은 구현자 판단.
- **막힘**: 막힐 때 기존 '막힘' 표시와 막는 소리를 낸다. 서버의 피해 판정은 탄·벽은 탄마다 한 번, 봉인·빔·레이저는 패턴마다 한 번, 내려찍기·안전지대·분노는 단발이라 무적 없이도 `coop:hit`이 틱마다 쏟아지지 않는다. 별도 묶음 처리는 필요 없다.
- **피드 구분**: `coop:hit`에 보호막으로 막았는지 구분하는 값을 더해, 동료 피드에 아이템 '방어막'이 아니라 '보호막'으로 표시한다.
- **클라이언트 예측**: 클라이언트는 탄 피격을 미리 계산해 맞은 연출과 무적을 혼자 건다(`client/src/main.ts`의 `checkBulletHit`, 지금 `guardUntil`을 검사하는 곳). 여기에 보호막이 켜져 있으면 건너뛰는 검사를 더한다.
- **켜는 소리**: 새 효과음을 하나 만든다. 기존 효과음 모듈(`client/src/audio.ts`)의 방식을 따른다.
- **효과 줄이기**: 구체는 그대로 보이되 흔들림·반짝임 같은 움직임은 생략한다.
- **남은 횟수 표시 (PC)**: 협력전 HUD의 스페셜 게이지 근처에 보호막 아이콘과 남은 횟수, '우클릭' 안내를 둔다. 엑스퍼트(0회)에서는 표시하지 않는다.
- **안내 문구**: 게임 방법·대기실 등 협력전 설명이 있는 곳에 우클릭 보호막 한 줄을 더한다. 구체 위치는 구현자 판단.

## 수치 (초기값, `RULES.coop.barrier`)

| 항목 | 값 |
|---|---|
| 지속 시간 `durationMs` | 1500 |
| 판당 횟수 `uses` | 이지 3, 노말 2, 하드 1, 엑스퍼트 0 |

난이도별 횟수는 `RULES.coop.levels[level]`에 두어도 되고 `barrier.uses`에 난이도 키로 두어도 된다(구현자 판단). 규칙 수치는 `shared/src/rules.ts`의 `RULES`에서만 바꾼다.

## 데이터와 메시지

- `CoopFx`(`shared/src/coopItems.ts`)에 `barrierUntil`, `barrierLeft`를 더한다. 이미 플레이어 상태로 전송·재접속되는 구조이므로 그 길을 탄다. 판 시작 시 `barrierLeft`를 난이도 횟수로 채운다.
- 새 클라이언트→서버 이벤트 `coop:barrier` (인자 없음). `server/src/index.ts` → `room.ts` → `coop.ts`로 연결한다(`coop:special`과 같은 경로).

## 테스트 (구현 후 한꺼번에)

- 사용 조건별 거부와 횟수 차감, 엑스퍼트 0회.
- 켜진 동안 관통 대상을 뺀 모든 피해 종류 막힘, 압살·분노·큰 구체 놓침 관통, 아이템 방어막 미소모.
- 종료 뒤 다시 피해, 일시정지 시간 보정, 재접속 상태 유지.
- 클라이언트: 우클릭이 `game:click`을 보내지 않음.

## 구현자에게 맡긴 것

모바일 버튼의 위치·모양, 구체의 정확한 색·크기·사라짐 연출, 막힘 표시 묶음 간격, 켜는 소리의 음색, HUD 배치, 횟수 설정 위치.
