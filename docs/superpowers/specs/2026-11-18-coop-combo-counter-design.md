# 협력전 콤보 상한과 폭딜 반격 설계

2026-11-18. 협력전(보스 레이드) 전용.

## 의도

콤보를 쌓을수록 보스에게 넣는 피해가 확실히 늘어나야 한다. 다만 그 보상이 과해져서 보스를 순식간에 녹이는 일은 막는다. 이를 위해 두 장치를 둔다.

- **콤보 상한 상향**: 콤보 보너스를 키우되 상한을 둔다.
- **폭딜 반격**: 팀이 짧은 시간에 피해를 몰아 넣으면 보스의 '분노 게이지'가 차고, 가득 차면 피할 수 없는 반격으로 모두의 콤보를 0으로 되돌린다.

## 목표

- 콤보 보너스는 10콤보마다 +0.2배, 상한 1.8배(40콤보)다. 지금은 10콤보마다 +0.1배, 상한 1.5배다.
- 분노 게이지는 팀 전체 피해를 합쳐서 계산한다. 보스 체력이 인원수에 비례하므로 최대 체력에 대한 비율로 센다.
- 난이도가 높을수록 게이지가 쉽게 찬다. 아래 '난이도별 감각'을 맞추는 것이 목표다.
- 게이지가 화면에 보여서 팀이 속도를 조절해 반격을 늦출 수 있다.
- 반격 순간 우클릭 보호막을 켜 두면 자기 콤보를 지킨다.

## 하지 않는 것

- 반격으로 체력 피해, 기절, 탈락을 주지 않는다. 콤보만 0이 된다.
- 스페셜 어택, 미사일 아이템, 수정 타격은 게이지에 넣지 않는다. 이들은 콤보 배율을 받지 않는 별도 보상이다.
- 아케이드와 다른 모드의 콤보는 건드리지 않는다.
- 보스 체력(`hpBase` 300)은 이번에 바꾸지 않는다. 콤보 상향으로 처치가 빨라지는 정도는 실제 플레이로 보고 따로 조정한다(내 판단).

## 실패로 보는 것

- 반격이 이유를 알 수 없이 콤보를 빼앗는 느낌을 준다. 예고와 게이지는 필수다.
- 이지에서 평범하게 잘하는 플레이에도 반격이 자주 나온다.
- 큰 피해 구간(수정 파훼 직후)에 반격이 나온다.

## 난이도별 감각 (사용자 승인)

| 난이도 | 반격이 나오는 때 | 재사용 대기 |
|---|---|---|
| 이지 | 최대 콤보로 다 잡아도 안 나옴. 아이템 강화가 두 개쯤 겹쳐야 나옴 | 30초 |
| 노말 | 최대 콤보에 아이템 강화 하나가 붙으면 나옴 | 25초 |
| 하드 | 최대 콤보로 거의 다 잡으면 몇 초 뒤 나옴 | 20초 |
| 엑스퍼트 | 최대 콤보면 금방 나옴. 콤보를 길게 끌기 어려움 | 15초 |

## 접근 방식

검토한 반격 기준은 두 가지였다.

- **팀 합계 (채택)**: 모두의 피해를 합산한다. 체력이 인원수에 비례하므로 공평하다.
- **사람마다 따로**: 원인이 분명하지만, 4인 방에서는 한 명이 기준에 닿기 어려워 인원수 보정이 따로 필요하다.

검토한 반격 형태는 세 가지였다.

- **내려찍기 재사용**: 피할 수 있는 공격.
- **충격파 고리**: 피할 수 있지만 작업이 크다.
- **피할 수 없는 화면 전체 공격 (채택)**: 사용자가 원래 생각한 형태다. 대응은 게이지를 보고 속도를 조절하는 것과 보호막이다.

검토한 게이지 계산 방식은 두 가지였다.

- **새는 양동이 (채택)**: 피해만큼 차고 매초 일정량 빠진다. 게이지가 부드럽게 움직인다. 난이도마다 '빠지는 속도'와 '용량' 두 값으로 감각을 맞추기 쉽다. 일시정지와 재접속 처리가 단순하다.
- **최근 3초 합계**: 직관적이다. 하지만 오래된 피해가 빠질 때 게이지가 덜컥거리고, 기록 목록을 들고 있어야 한다.

## 동작

### 콤보 보너스

`orbDamage`의 콤보 보너스는 `min(floor(combo / 10) × 0.2, 0.8)`이다. 기존 식에 `RULES.coop.comboPer`와 `comboCap` 값만 바꿔 넣는다. 콤보 보너스는 원과 약점 피해에 적용되며, 지금과 같다.

### 분노 게이지

- 단위는 '보스 최대 체력 대비 %'이고, 값 범위는 0부터 용량까지다.
- 콤보 배율을 받는 피해, 곧 `orbDamage`를 거친 피해(원·약점)가 실제로 깎은 체력만큼 찬다. 계산은 `dealt / maxHp × 100`이다. 봇의 피해도 포함한다.
- 매초 `drain`만큼 빠진다. 서버는 피해가 들어올 때와 매 틱마다 경과 시간만큼 뺀다.
- 다음 동안에는 게이지가 차지 않는다.
  - 큰 피해 구간
  - 수정 보호막 단계
  - 반격 예고 중
  - 재사용 대기 중
  - 일시정지 중
- 게이지가 용량에 닿으면 반격 예고를 시작한다.

### 난이도별 수치 (초기 조정값, 내 판단)

계산 근거: 1.8배 콤보로 원을 모두 잡을 때 피해는 최대 체력 대비 초당 이지 약 1.43%, 노말 1.25%, 하드 1.16%, 엑스퍼트 0.87%다. 원 간격 배율 `orbMult`와 체력 배율 `hpMult`를 반영했고, 노란 원 20%를 섞었다.

| 난이도 | 빠지는 속도 (%/초) | 용량 (%) | 재사용 대기 |
|---|---|---|---|
| 이지 | 2.3 | 5 | 30초 |
| 노말 | 1.3 | 2.5 | 25초 |
| 하드 | 0.8 | 1.5 | 20초 |
| 엑스퍼트 | 0.5 | 1.0 | 15초 |

- **이지**: 최대 콤보로는 들어오는 양이 빠지는 양보다 적어 차지 않는다. 공격력 강화와 화력 강화가 겹치면(약 2.4배) 5초 남짓에 찬다.
- **노말**: 최대 콤보만으로는 거의 차지 않는다. 화력 강화(1.5배)가 붙으면 약 4초에 찬다.
- **하드**: 최대 콤보로 90% 이상 잡으면 약 6초에 찬다.
- **엑스퍼트**: 최대 콤보에서는 약 3~4초, 20콤보(1.4배)에서도 5~6초에 찬다.

### 반격

1. **예고 `warnMs` 2초**: 화면에 '보스 반격!'과 남은 시간을 띄운다. 보호막이 있는 난이도에서는 '보호막으로 콤보를 지키세요', 엑스퍼트에서는 '콤보가 초기화됩니다'를 함께 보여 준다.
2. **발동**: 화면 전체가 번쩍인다. 살아 있는 모든 플레이어(봇 포함)의 콤보가 0이 된다.
   - 그 순간 우클릭 보호막이 켜져 있으면 콤보를 지킨다. 지연 여유는 양쪽에 준다(내 판단). 서버는 발동 시각 `at`에 연출을 보내고, 콤보 판정은 `at + lagMs`에 한다. 보호막이 켜진 구간을 `lagMs`만큼 늘린 구간이 발동 시각 `at`에 걸치면 지킨 것으로 본다. 이 구간은 `barrierUntil − 지속시간`부터 `barrierUntil + lagMs`까지다. 이렇게 하면 발동 직전에 눌렀는데 요청이 조금 늦게 도착한 경우도 인정된다.
   - 보호막 사용 횟수는 따로 소모하지 않는다. 켤 때 이미 소모되었다. 반격 전용 횟수는 두지 않고, 기존 판당 횟수(이지 3·노말 2·하드 1·엑스퍼트 0)를 탄 막기와 함께 쓴다(사용자 결정). 생존에 쓸지 콤보 지키기에 쓸지 고르는 선택이 생긴다.
   - 아이템 방어막(`guard`)은 반격을 막지 않는다(내 판단). 이것은 한 번 맞을 공격을 막는 아이템이고, 반격은 피해가 없는 공격이기 때문이다.
3. **발동 뒤**: 게이지는 0이 되고 재사용 대기가 시작된다. 대기 동안 게이지는 0에 머물며 흐리게 표시된다.
4. **취소**: 예고 중에 수정 보호막 단계가 시작되면 반격을 취소하고 게이지를 0으로 만든다. 재사용 대기는 시작하지 않는다. 판이 끝나도 취소한다.
5. **기록**: 콤보를 잃은 사람마다 반격 횟수를 통계에 남긴다. 동료 피드에는 '반격으로 콤보 초기화' 또는 '보호막으로 콤보 지킴'을 띄운다.

### 일시정지와 재접속

- 일시정지가 끝나면 예고 발동 시각과 재사용 대기 종료 시각을 일시정지 시간만큼 민다. 게이지는 일시정지 중에 빠지지 않는다.
- 재접속 상태와 `coop:state`에 다음 값을 싣는다.
  - 게이지 값과 그 값을 기록한 서버 시각
  - 빠지는 속도와 용량 (또는 난이도로 화면이 계산)
  - 예고 발동 시각
  - 재사용 대기 종료 시각
- 화면은 받은 값에서 경과 시간만큼 빼서 부드럽게 그린다.

### 화면

- **분노 게이지**: 보스 체력 바 바로 아래에 얇은 붉은 막대로 둔다. 가득 차 갈수록 진해진다. 재사용 대기 중에는 흐리게 표시하고 남은 시간을 보여 준다.
- **예고**: 2초 동안 보스가 붉게 맥동하고 경고 문구를 띄운다. 반격 소리는 새로 만들거나 기존 경고음을 재사용한다(만드는 사람 판단).
- **발동**: 화면 전체가 붉게 한 번 번쩍인다. 효과 줄이기를 켜면 번쩍임 없이 테두리만 잠깐 붉게 한다.
- 콤보를 잃으면 내 콤보 숫자가 깨지는 연출을 한다. 지켰으면 기존 '막음!' 연출을 재사용한다.
- 대기실 협력전 설명(스페셜 어택 설명 근처)에 한 줄을 넣는다: "피해를 너무 몰아 넣으면 보스가 반격해 콤보가 0이 됩니다."

## 수치 위치

모든 수치는 `shared/src/rules.ts`의 `RULES.coop`에 둔다.

```ts
comboStep: 10, comboPer: 0.2, comboCap: 0.8,
counter: {
  warnMs: 2_000,
  drain: { easy: 2.3, normal: 1.3, hard: 0.8, expert: 0.5 } as Record<CoopLevel, number>,
  cap: { easy: 5, normal: 2.5, hard: 1.5, expert: 1 } as Record<CoopLevel, number>,
  cooldownMs: { easy: 30_000, normal: 25_000, hard: 20_000, expert: 15_000 } as Record<CoopLevel, number>,
},
```

## 만드는 사람에게 맡기는 것

- 게이지 계산 함수를 `shared`의 순수 함수로 둘지(테스트하기 좋음) 서버 클래스 안에 둘지
- 이벤트를 따로 둘지(예: `coop:counter`) `coop:state`에 합칠지
- 반격 연출의 세부 모양, 소리, 문구의 정확한 표현
- 통계 필드 이름과 결과 화면에 반격 횟수를 보여 줄지 여부

## 테스트

모든 기능을 구현한 뒤 한꺼번에 작성한다.

- 콤보 보너스 계산: 0·10·39·40·100콤보
- 게이지가 차고 빠지는 계산
- 큰 피해 구간, 보호막 단계, 대기 중에는 차지 않는지
- 스페셜 어택과 미사일이 게이지를 채우지 않는지
- 예고 뒤 발동: 콤보 초기화와 보호막으로 지키기 (`lagMs` 경계 포함)
- 보호막 단계 시작 시 취소
- 일시정지 시간 보정
- 재접속 상태에 게이지가 실리는지
