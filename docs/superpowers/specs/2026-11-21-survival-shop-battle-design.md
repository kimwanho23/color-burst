# 서바이벌 · 상점전 설계 (오토체스형: 체력·골드·상점)

> 이 모드는 대화에서 처음 "체력전(오토체스형)"이라 부르던 것이다. 사용자가 **"체력전"**이라는 이름을 공격 대상 방식의 모드에 쓰기로 해서, 이 골드·상점 모드는 **"상점전"(가칭)**으로 이름을 바꿨다. 상점전을 만들지는 사용자가 정한다("인기 없으면 나중에 없앤다" 방침). 체력전을 먼저 만들고 상점전은 그 뒤에 판단한다.

## 의도

- 아케이드는 한 판이 짧아서 빌드가 자랄 시간이 없다(증강 선택 6번). 체력으로 오래 버티는 **라운드 반복형**이면 선택이 쌓여 빌드가 의미를 가진다.
- 오토체스의 핵심을 가져온다: **순위에 따라 체력이 깎이고, 연승/연패와 순위에 따라 골드를 받고, 골드로 증강을 산다.** 증강이 공짜 3택 1이 아니라 한정된 돈을 쓰는 결정이 된다.
- 증강 가격이 곧 **힘 조절 수단**이 된다. 지금 아케이드는 편식가·콤보 장인 같은 카드가 훨씬 세서 빌드가 쏠리는데(점수·콤보 카드 레전드 +55~86%, 피버 카드 +10%대, 어제 시뮬레이션), 가격으로 차이를 메울 수 있다.
- 사용자 결정: 서바이벌 안의 하위 모드(상점전)이고, "증강 가격은 골드에 따라 선택"한다. 승패는 순위로 가른다.

## 목표 / 하지 않는 것 / 실패 기준

**목표**
1. 라운드마다 전투 → 정산(체력·골드) → 상점을 반복하고, 체력이 0이 되면 탈락, 마지막 1명이 승리한다.
2. 상점에서 골드로 증강을 사고 새로고침한다. 빌드가 6번 선택이 아니라 **10라운드 안팎의 소비 결정**으로 자란다.
3. 기존 아케이드의 증강·조합·시너지 코드를 **그대로 재사용**한다(카드 정의, `applyPick`, 도감).
4. 승부가 한 판(5~12라운드, 약 5~8분) 안에 끝난다.

**하지 않는 것**
- 증강 자체의 수치 변경. 가격은 새로 정하되 카드 효과는 건드리지 않는다.
- 저주·특별 카드·유니크 카드의 상점 판매(1차 범위 밖, "열어 둔 것"). 일반 증강만 판다.
- 팀전, 협력전과의 결합.
- 증강 판매(되팔기), 증강 잠금(다음 라운드로 남기기).

**실패 기준**
- 연승한 사람이 골드까지 독식해 눈덩이처럼 이기고, 연패한 사람이 회복할 수 없는 것(연패 보너스와 순위 보너스로 완화해야 한다).
- 상점 단계가 길어져 판이 늘어지는 것(시간 제한과 전원 준비 시 즉시 진행).
- 기존 아케이드·서바이벌·클래식 동작이 바뀌는 것.

## 규칙 (초안 수치, 모두 시뮬레이션으로 확정)

수치는 `shared/src/rules.ts`의 `RULES.shopBattle`에 둔다(프로젝트 규칙: 규칙·밸런스 수치는 `RULES`에서만 바꾼다).

### 체력과 라운드

| 항목 | 값 | 설명 |
|---|---|---|
| 시작 체력 | 100 | 막대로 표시 |
| 라운드 길이 | `arcadeRoundSec`(기본 30초) | 방 규칙의 아케이드 라운드 시간 재사용 |
| 점수 | **라운드 시작에 0으로 초기화** | 그 라운드 점수는 순위를 정하는 데만 쓴다. 누적 점수는 없다(사용자 확인). 이렇게 하면 1등·꼴찌를 기준으로 하는 기존 효과(하이에나, 꼴찌 보정, 역전 기회, 1등 저격 봇)가 자연스럽게 "이번 라운드 기준"이 된다 |
| 순위 | 라운드 점수, 같으면 콤보, 그래도 같으면 무작위 | `ranking`/`pickOut` 도우미 재사용 |
| 승/패 | 살아 있는 인원의 **상위 절반(올림)이 승**, 나머지가 패 | 4명: 1·2등 승, 3·4등 패 / 3명: 1·2등 승, 3등 패 / 2명: 1등 승, 2등 패 |

### 체력 피해 (패한 사람만)

`damage = round(base(라운드) × 순위계수)`

- `base(라운드) = 6 + 1.5 × 라운드` (1라운드 7.5 → 8, 6라운드 15, 10라운드 21)
- 순위계수: 하위에서 1등급 위(예: 4명일 때 3등) 1.0, 최하위 1.5. 인원이 줄면 패자 수가 줄어 자연히 계수가 같아진다.
- 승자는 피해 0.
- 체력이 0 이하가 되면 탈락. 같은 라운드에 여럿이 0이 되면 **그 라운드 점수가 높은 쪽이 오래 버틴 것**으로 순위를 매긴다.
- 안전장치: 라운드 15에 도달하면 피해에 `+50%`가 붙고 20라운드마다 추가로 더해진다(무한 지연 방지). (내 판단)

### 골드

| 항목 | 값 |
|---|---|
| 시작 골드 | 4 |
| 기본 수입 | 라운드마다 +5 |
| 순위 보너스 | 1등 +3, 2등 +2, 3등 +1, 4등 0 (인원이 줄면 뒤에서부터 줄어듦) |
| 연승/연패 보너스 | 같은 결과(승 또는 패)가 2회 연속 +1, 3~4회 +2, 5회 이상 +3. 승과 패에 **모두** 준다(연패의 안전망) |
| 이자 | 보유 골드 10당 +1, 최대 +5 (모으는 선택을 만든다) |

- 라운드가 끝나는 정산 때 한 번에 지급한다. 골드는 정수.
- 탈락한 사람은 골드를 받지 않는다.

### 상점

- 정산 뒤에 상점 단계가 열린다. 사람마다 **개인 상점**이 따로 있다(다른 사람과 같은 카드를 사는 경쟁은 없다).
- 진열: 일반 증강 **5장**. 각 칸의 등급은 `TIER_ODDS`(아케이드의 라운드별 등급 확률 표)를 라운드 번호로 인덱싱해 굴린다. 표 길이를 넘는 라운드는 마지막 행을 쓴다. 이미 상한(`cap`)에 닿은 증강과 이 방에서 효과가 없는 증강(`offPool`)은 뺀다. (아케이드 `rollOptions` 재사용)
- **가격**: 등급으로 정한다. 초안: 노말 2, 레어 4, 에픽 7, 레전드 11. 카드별 가격 보정은 시뮬레이션에서 점수 기여가 뚜렷하게 높은 카드에만 둔다(`PRICE_ADJUST` 표). 처음에는 등급 가격만 쓴다.
- 새로고침: 2골드. 라운드마다 **첫 한 번은 무료**. 진열은 라운드가 끝나면 사라진다(잠금 없음).
- 구매: 카드를 누르면 골드가 줄고 `applyPick`으로 즉시 적용된다. 한 라운드에 여러 장 살 수 있다.
- 시간: 25초(`RULES.hpBattle.shopSec`). **모두 [준비 완료]를 누르면** 바로 다음 라운드로 간다.
- 저주·특별·유니크는 진열되지 않는다(1차). `rollOptions`의 옵션으로 저주 확률을 0으로 하고 특별·유니크를 끈다. (`RollOpts`에 `shop: true`를 더해 저주·특별·유니크를 한 번에 끈다. 지금 `RollOpts`는 `curses`·`allLegend`·`forceCurse`·`exclude`·`minTier`·`guarantee` 등을 갖는다.)

### 끝

- 살아 있는 사람이 1명이 되면 게임 종료, 그 사람이 1위. 탈락 순서의 역순이 순위(`survivalRanking`).
- 마지막 라운드의 동시 탈락은 그 라운드 점수 순으로 정한다.

## 서버 구현 (규칙 객체 `kind: 'shop'`)

`SurvivalRuleset`(재구성 문서) 구현. 새 파일 `server/src/survival/shopBattle.ts`.

- `setup`: 모든 플레이어 `hp = RULES.hpBattle.hp`, `gold = RULES.hpBattle.startGold`, `streak = {type:'win'|'lose'|null, n}`. 이미 있는 `PlayerState.hp`(협력전이 씀)를 재사용하고, `gold`, `streak`는 새 필드(`PlayerState`에 추가, `newPlayer`·`resetForRound`에서 초기화)다.
- `onRoundStart`: **모든 플레이어 `score = 0`, `roundStart = 0`** (이전 라운드 효과 정산이 끝난 뒤). 증강 스택·성장 칸은 유지된다. `startRound`가 라운드 시작 상태를 만드는 지금 경로를 그대로 쓴다.
- `settle(round, alive)`: ① 순위 매김 ② 승/패 구분 ③ 체력 피해 적용, `hp ≤ 0`이면 `eliminate` ④ 연승/연패 갱신 ⑤ 골드 지급 ⑥ 정산 결과(`hp:round` 이벤트: 사람마다 순위·피해·골드 내역)를 방에 보냄 ⑦ 남은 사람이 1명이면 `over: true`.
  - 저주 정산(`applyRoundCurses`)과 랜덤 이벤트는 상점전에서 쓰지 않는다. (저주 카드가 없다. 랜덤 이벤트는 방 규칙 확률을 0으로 강제한다. 라운드 테마도 끈다. 내 판단)
- `intermission`: `'shop'`.
- 상점 상태: `Map<playerId, Shop>`, `Shop = { cards: {pick: Pick, price: number}[], rerolled: number }`. 라운드마다 `rollShop(p, round)`로 새로 굴린다. 서버가 가격·골드·상한을 모두 검사한다(클라이언트 신뢰 금지).
- 봇: 상점 단계에서 `botShop`이 약간의 지연 뒤 구매한다. 규칙: 살 수 있는 가장 높은 등급 카드를 사고, 같은 분류에 몰리도록 가중치를 준다(`bot.ts`의 증강 선택 로직 재사용). 새로고침은 하지 않는다.

### 프로토콜 (`shared/src/protocol.ts`)

| 방향 | 이벤트 | 내용 |
|---|---|---|
| 서버 → 클라 | `hp:round` | 정산 결과 `{ round, results: {id, rank, win, dmg, hp, gold, income:{base, rank, streak, interest}}[] }` |
| 서버 → 클라 | `shop:state` | 내 상점 `{ gold, cards: {pick, price, sold}[], rerollCost, endsAt, ready }` (재접속 때도 받는다) |
| 클라 → 서버 | `shop:buy` | `{ index }` |
| 클라 → 서버 | `shop:reroll` | 없음 |
| 클라 → 서버 | `shop:ready` | 없음 (준비 완료, 한 번 누르면 되돌릴 수 없음) |
| 서버 → 클라 | `player:update` 등 기존 | `hp`, `gold`, `streak`를 `PlayerState`에 담아 보낸다 (이미 `hp`는 있음) |

`arcade:offer`/`arcade:choose`/`arcade:reroll`은 쓰지 않는다. 아케이드 선택 흐름을 건드리지 않기 위해서다.

## 화면 (클라이언트)

### 전투 중

- 점수판(`#scores`): **체력 막대**(협력전의 `myhp` 모양 재사용)와 골드 아이콘 숫자가 가장 크게 보인다. 이번 라운드 점수는 순위를 가리는 용도라 작게 둔다(체력이 주인공이다). 연승/연패는 이름 옆 작은 불꽃/물방울 아이콘과 횟수.
- 라운드 시작 배너: `라운드 3`과 지금 순위에 따른 위험 표시(최하위 2명 하이라이트는 하지 않는다. 억울함 방지).

### 정산 화면 (라운드 사이 첫 2초)

```
라운드 3 결과
 1등  지은   승 +3골드 (연승 2)
 2등  민수   승
 3등  봇 A   패  체력 −12  → 88
 4등  나     패  체력 −18  → 82     (연패 3: 골드 +2)
```

- 사람마다 한 줄: 순위, 승/패, 체력 변화(막대가 줄어드는 짧은 애니메이션, 효과 줄이기 시 정적), 골드 수입 내역.

### 상점 화면

```
┌ 상점 · 라운드 3 ───────────────────────── 남은 시간 22초 ┐
│ 내 골드 7  (이자 +0)   체력 82/100                         │
│ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐                    │
│ │카드1 │ │카드2 │ │카드3 │ │카드4 │ │카드5 │   ← 5장, 각 카드에 가격  │
│ │ 4금  │ │ 2금  │ │ 7금  │ │ 2금  │ │ 11금 │                    │
│ └─────┘ └─────┘ └─────┘ └─────┘ └─────┘                    │
│ [새로고침 2금(첫 번째 무료)]   [내 증강 12개 ▾]  [준비 완료] │
└──────────────────────────────────────────────────────────┘
```

- 카드는 아케이드 선택 카드(`acard`)의 모양을 재사용하고 가격 배지를 더한다. 골드가 모자라면 가격을 빨갛게 하고 누를 수 없다.
- 내 증강 목록과 조합 진행도는 지금 선택 화면의 표시(`arcadeUI.ts`의 `buildTiles`, `buildSummary`, `comboList`) 재사용.
- [준비 완료]를 누르면 "다른 사람 기다리는 중" 표시. 다른 사람 상점 상태는 보이지 않고 **누가 준비했는지만** 점으로 보인다.
- 시간이 다 되면 산 것만 남기고 자동 진행.

### 결과 화면

- 순위는 탈락 순서. **체력 그래프**(`graphBox`): 라운드별 체력 변화를 사람마다 선으로(지금의 점수 그래프 자리). 점수 출처 통계(`srcBox`)는 판 전체 누적 대신 사람마다 합산을 보인다(기존 `addSrc`는 그대로 누적되므로 재사용 가능).
- 칭호는 서바이벌 결과에 맞게 후속으로 정한다.

## 구현 범위와 순서 (빌더용)

1. `shared`: `RULES.shopBattle` 수치, `PlayerState.gold`·`streak`, 순수 함수 `hpDamage`, `goldIncome`, `streakNext`, `rollShop`(`rollOptions` 활용), 가격표. 단위 테스트(`shared/test/shopbattle.test.ts`).
2. `server/src/survival/shopBattle.ts`: 규칙 객체 + 상점 상태·검증 + 봇 상점. 소켓 이벤트 등록(`server/src/index.ts`), 재접속 때 `shop:state` 복구, 일시정지 때 상점 시간 밀기.
3. 클라이언트: 점수판 체력·골드, 정산 화면, 상점 화면, 결과 체력 그래프. (재구성 문서의 모드 선택 UI가 먼저 있어야 시작할 수 있다.)
4. **시뮬레이션**: 서버 `Room`을 가상 시계와 고정 시드로 돌려 판 길이, 연승 눈덩이, 카드 구매 분포를 확인한다. 어제 시뮬레이션 스크립트는 저장소에 없다. 이 작업과 함께 `scripts/sim/`에 넣어 재사용 가능하게 한다. 확인할 것: 평균 라운드 수 7~10, 최하위 연패자가 3라운드 안에 탈락하지 않을 것, 등급별 구매율이 한쪽으로 쏠리지 않을 것.

## 완료 기준

- 4명 방에서 상점전을 시작해 라운드 → 정산 → 상점이 반복되고 마지막 1명이 이긴다. 봇만 있는 방에서도 끝까지 돈다.
- 정산: 패한 사람만 체력이 깎이고 `damage` 공식과 같으며, 골드 수입 내역(기본·순위·연승/연패·이자)이 화면에 보인다.
- 상점: 골드가 모자라면 못 사고(서버도 거절), 산 증강이 바로 다음 라운드에 적용되며, 새로고침 첫 번째는 무료다. 모두 준비하면 25초 전에도 진행한다.
- 재접속하면 체력·골드·상점 상태가 복구된다. 일시정지가 상점 시간도 멈춘다.
- 아케이드·클래식·협력전·라운드 탈락의 기존 테스트가 그대로 통과한다.
- 시뮬레이션에서 평균 라운드 수와 연패 회복이 위 기준을 만족한다.
- `npm test`, `npm run typecheck`, `npm run build`가 통과한다.

## 내가 정한 것 (검수 때 확인)

- **(사용자 확인 2026-11-21)** 상점전은 점수를 쌓는 모드가 아니라 **라운드마다 피해를 가하는** 모드다. 그래서 점수는 라운드마다 0으로 초기화하고(누적 점수 없음), 점수는 그 라운드의 순위를 가리는 데만 쓴다. 피해량은 점수 차이에 비례하지 않고 순위·라운드로 정해지는 고정 공식이다.
- 모든 수치(체력 100, 피해 공식, 골드, 가격, 이자, 새로고침)는 초안이다. 오토체스의 구조를 따랐다.
- 승/패는 상위 절반(올림)/하위 절반.
- 개인 상점(다른 사람과 같은 진열을 보지 않는다), 상점 5장.
- 저주·특별·유니크는 1차에서 팔지 않는다. 랜덤 이벤트·라운드 테마·저주 정산은 끈다.
- 새 이벤트 이름(`shop:*`, `hp:round`)과 `PlayerState.gold`·`streak` 필드.
- 판 길이 안전장치(라운드 15부터 피해 +50%).
