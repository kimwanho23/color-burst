# 튜토리얼 멈춤 설명 · 도감 기본 규칙 점수 설계 (2026-11-17)

## 목적

지금 튜토리얼(2026-11-09, `2026-11-09-tutorial-design.md`)은 위쪽 띠에 문구만 바뀌고 판은 멈추지 않는다. 처음 하는 사람이 무엇을 왜 하는지 모른 채 원을 누르게 된다. 보통 게임 튜토리얼처럼 **판이 멈추고, 짚어 준 것만 해 보게 하고, 덧붙여 설명한 뒤, 자유롭게 연습**하는 흐름으로 바꾼다.

함께 바꾸는 것: 도감의 점수 배율은 방 규칙과 상관없이 **기본 규칙(1배율) 기준**으로 쓰고, 그 방의 실제 점수는 **대기실**에서 본다.

## 정한 것 (사용자 결정)

- 단계 순서와 내용: ① 원 잡기(내 색 원과 노란 원 차이) → ② 콤보(콤보 보너스) → ③ 견제(견제하기, 봇에게 견제 당하기, 표적 기초) → ④ 피버(피버 중 효과). 빠진 기초는 추가해도 된다 → ⑤ 점수 구역, ②의 빈 곳 클릭, ③의 반격을 추가(제안, 아래 '내가 정한 것').
- 점수 배율은 규칙·증강에 따라 바뀌므로 튜토리얼 문구에는 숫자를 쓰지 않는다. 예: "피버 중에는 점수가 크게 늘어나요".
- 만드는 방법은 **서버가 판을 멈춘다**(A안).
- 멈춘 순간에는 **시킨 동작 하나만** 판정한다. 원을 누르라고 했으면 그 원만, 빈 곳을 누르라고 했으면 빈 곳만. 그 밖의 클릭은 아무 일도 일으키지 않는다.
- 튜토리얼에서도 **Esc로 나가기**를 할 수 있어야 한다.
- 도감 점수는 기본 규칙 기준 + "방 규칙에 따라 달라질 수 있어요" 안내. 지금 방 규칙의 점수는 대기실에서 본다.

## 만드는 방법 (고른 것과 버린 것)

| 안 | 내용 | 결정 |
|---|---|---|
| A. 서버가 멈춘다 | 튜토리얼 방이 정해진 순간 판 시각을 멈추고, 받을 동작을 정해 둔다. 일시정지와 같은 시각 밀기를 쓰되 일시정지 화면·3초 카운트다운은 없다 | **고름**. 멈추는 순간이 정확하고, 봇 견제 같은 장면을 서버가 확실히 만들 수 있으며, 튜토리얼 방이 이미 서버에 있다 |
| B. 화면이 일시정지를 요청 | 화면이 카드를 띄우며 기존 `game:pause` | 버림. 요청이 닿는 사이 원이 움직이고, 풀 때 일시정지 화면·카운트다운이 끼어든다 |
| C. 단계 시작 때만 설명 | 빈 판에서 설명 후 시작 | 버림. 원한 "게임 중간에 멈춤"이 아니다 |

## 1. 흐름의 단위: 장면(beat)

각 단계는 장면 목록이다. 장면은 세 종류.

| 종류 | 판 | 받는 동작 | 끝나는 때 |
|---|---|---|---|
| `focus` 짚어 주기 | 멈춤. 짚은 대상 말고는 어둡게 | `accept`가 `circle`이면 짚은 원 클릭만, `empty`면 빈 곳 클릭만 | 그 동작을 하면 판정(점수·콤보 등 평소대로) 후 다시 움직임 |
| `card` 설명 카드 | 멈춤 | 카드 클릭 또는 [계속] (`tutorial:next`) | 누르면 다시 움직임 |
| `free` 자유 연습 | 움직임 | 평소 튜토리얼 판정(헛클릭은 콤보만 끊김, 감점·게이지 감소 없음) | 목표를 채우면 다음 장면 |

- 장면이 바뀔 때 서버가 `tutorial:beat`를 보낸다(아래 6절). 띠의 진행 수는 `free` 장면에서만 보인다.
- `focus`의 대상 원은 서버가 그 장면에서 새로 만든다(`forceKind`). 원은 가운데에서 바깥으로 날아가므로, 나온 뒤 `RULES.tutorial.focusDelayMs`(600ms)가 지나 가운데에서 떨어졌을 때 멈춘다. 멈춘 동안 사라지지 않는다. 짚기 장면이 시작되면 그 장면이 끝날 때까지 다른 원은 새로 나오지 않는다.
- 점수 구역 장면의 대상 원은 가장자리 구역에 있을 때 멈춘다.
- 다시 움직일 때 카운트다운은 없다. 멈춘 시간만큼 원·버프·피버·표적 시각을 민다(`finishResume`과 같은 `shiftTimes`).

### 멈춘 동안의 입력 (꼭 지킬 것)

- 서버: `focus`에서 `accept`와 맞지 않는 클릭은 **아무 처리도 하지 않는다**. 헛클릭 판정, 헛손질 보정(`nearestMine`), 넓은 손 범위 잡기, 자석 모두 건너뛴다. `card`에서는 모든 판 클릭을 무시한다.
- 화면: 같은 경우 클릭 효과·소리를 내지 않는다. 대신 짚은 대상 쪽을 한 번 깜빡여 어디를 눌러야 하는지 다시 알린다.
- `accept: 'empty'`는 원 위가 아닌 판 안 클릭만. 원 위를 누르면 무시한다.
- 클릭 속도 제한은 그대로 둔다.

## 2. 단계별 장면 (문구는 초안, 숫자 없음)

### ① 원 잡기 `own`
1. `focus` 내 색 원 · "이게 내 색 원이에요. 눌러 보세요"
2. `card` "내 색 원은 나만 잡을 수 있어요. 잡으면 점수가 오르고 피버 게이지가 차요"
3. `focus` 노란 원 · "노란 원은 누구나 잡을 수 있어요. 눌러 보세요"
4. `card` "노란 원은 내 색보다 점수가 조금 적지만, 먼저 잡는 사람이 가져가요. 피버 게이지도 채워요"

원은 한 번에 하나씩 짚고 바로 설명한다. 자유 연습은 없다.

### ② 콤보 `combo`
1. 단계 시작 때 콤보를 `RULES.tutorial.comboStart`(9)로 맞춘다.
2. `card` "쉬지 않고 연달아 잡으면 콤보가 올라요. 지금 콤보는 9예요"
3. `focus` 내 색 원 · "하나 더 잡아 콤보 10을 만들어 보세요"
4. `card` "콤보 10! 콤보가 10씩 쌓일 때마다 보너스 점수가 더 붙어요" (방금 받은 점수를 '원 점수'와 '콤보 보너스'로 나눠 보여 줘 차이를 짚는다. 숫자는 그 판에서 실제로 받은 값 그대로라 규칙이 바뀌어도 틀리지 않는다)
5. `focus` 빈 곳 (`accept: 'empty'`) · "이번엔 빈 곳을 눌러 보세요"
6. `card` "빈 곳을 누르면 콤보가 끊겨요. 실제 게임에서는 피버 게이지도 줄어요"

### ③ 견제 `steal` (봇 1명 등장, 시작 콤보 5)
1. `card` "다른 색 원은 다른 사람 원이에요. 잡으면 견제가 돼요"
2. `focus` 봇 색 원 · "봇 원을 잡아 견제해 보세요"
3. `card` "봇 콤보가 끊겼어요! 대신 내 콤보도 끊기고 피버 게이지가 줄어요. 잠깐 내가 표적이 돼요" (내 칩의 표적 표시를 짚음)
4. `free` 내 원 잡기 — 내 표적 시간이 끝날 때까지 (진행 수 없이 "표적이 풀릴 때까지 원을 잡아 보세요")
5. 봇이 내 색 원 하나를 잡는다(서버가 정해서 일으키는 견제, 평소 견제 판정 그대로). 그 직후 `card` "봇이 내 원을 가져가 내 콤보를 끊었어요. 이제 봇이 표적이에요" (봇 칩의 표적 표시를 짚음)
6. `focus` 봇 색 원 · "표적이 된 사람의 원을 잡으면 반격! 점수를 더 받아요"
7. `card` "견제하면 표적이 되고, 표적은 반격당해요"

### ④ 피버 `fever` (봇은 남아 있음, 클릭 안 함)
1. `card` "원을 잡으면 피버 게이지가 차요. 가득 차면 피버!" (게이지를 짚음)
2. 피버 게이지를 `RULES.tutorial.feverStart`(99%)로 맞춘다.
3. `focus` 내 색 원 · "원 하나만 더 잡으면 피버예요. 눌러 보세요" → 잡으면 피버 시작
4. 피버가 켜진 직후 `card` "피버 중에는 점수가 크게 늘어나요. 노란 원도 내 색이 되고, 남의 색 원을 잡아도 페널티가 없어요" (카드 동안 피버 시간은 멈춰 있음)
5. `free` 피버 중에 원 잡아 보기 — 피버가 끝날 때까지. 판: 내 색 + 노란 + 봇 색 원

### ⑤ 점수 구역 `zones`
1. `card` "판은 가운데 · 사이 · 가장자리로 나뉘어요. 바깥쪽에서 잡을수록 점수가 커져요" (구역 그림, `guideArt`의 `zones` 재사용)
2. `focus` 가장자리 구역의 내 색 원 · "가장자리에서 잡아 보세요"
3. `free` 사이·가장자리에서 원 3개 잡기

마지막 장면 뒤 지금처럼 "잘했어요!" → 연습 완료 화면.

## 3. 서버 (`server/src/tutorial.ts`, `server/src/room.ts`)

- 장면 목록은 데이터로 둔다: `RULES.tutorial`에 단계 순서 `['own', 'combo', 'steal', 'fever', 'zones']`, 목표 수치, 단계별 생성 설정, 피버 시작 게이지. 문구는 화면(`client/src/tutorial.ts`)에, 서버는 장면 id만 안다.
- `server/src/tutorial.ts`는 순수 판단만 맡는다: 이 장면의 받을 동작, `free` 진행 판정(지금 `progress` 확장: 원 수·콤보·피버 시작·피버 끝·표적 풀림·구역 안 잡기), 다음 장면.
- `room.ts`
  - 튜토리얼 상태 `tut`에 장면 번호와 멈춤 상태(`hold: { beat, circleId?, accept } | null`, 멈춘 시각)를 더한다.
  - 멈춤은 협력전 투표와 같은 **조용한 멈춤**을 쓴다: `pausedAt`을 세우고 `pausedBy = null`로 `game:pause { by: '' }`를 보내면 화면은 일시정지 창 없이 판만 멈춘다. 풀 때는 카운트다운(`beginResume`) 없이 `finishResume()`을 바로 부른다. (계획 단계에서 바꿈: 처음엔 따로 두려 했으나, 이미 있는 조용한 멈춤이 일시정지 화면·카운트다운 없이 같은 일을 한다)
  - `click` 처리 맨 앞에서 `hold`가 있으면 1절 규칙으로 걸러 낸다.
  - 새 이벤트 `tutorial:next`(카드 넘기기): 튜토리얼 방이고 `card` 장면일 때만.
  - 봇 견제 장면: 서버가 판 위 내 색 원 하나를 골라 봇 이름으로 `claim`. 그 원이 없으면 하나 만들고 판 안으로 들어온 뒤 잡는다.
  - 탭을 떠나 생기는 자동 일시정지(혼자 하기)는 그대로 둔다. 멈춤 장면 중이면 일시정지가 겹쳐도 풀린 뒤 멈춤 장면이 계속된다.
- 다시 접속하면 지금 장면(`tutorial:beat`)을 다시 보낸다.

## 4. 화면 (`client/src/tutorial.ts`, `main.ts`, `style.css`)

- `focus`: 판 전체를 어둡게 덮고 대상 원(또는 빈 곳 안내 영역) 자리만 뚫는다. 그 옆에 말풍선 한 줄. 대상 원이 작으면(색 원 크기 축소 규칙 등) 테두리를 키워 보이게.
- `card`: 판 가운데 카드(제목 없이 한두 줄 + 필요하면 작은 그림). 카드 아무 곳 클릭 또는 [계속]·Enter·Space.
- 표적 표시를 짚는 카드(③-3, ③-5)는 점수판 칩의 표적 표시에 화살표.
- 위쪽 띠: 단계 이름과 `free` 장면 진행 수. 멈춤 장면에서는 진행 수를 숨긴다.
- **Esc**: 튜토리얼에서는 일시정지 대신 기존 나가기 확인 창(`askLeave`, 문구 "연습을 그만할까요?")을 연다. P는 아무 일도 하지 않는다. [건너뛰기]는 그대로.

## 5. 도감과 대기실 점수표

- 도감 '규칙' 탭(`client/src/codex.ts`의 `rulesTab`): 방 안에서 열어도 늘 `DEFAULT_RULES`로 `scoreTable`을 만든다. 안내 문구: "기본 규칙 기준이에요. 방 규칙과 증강에 따라 달라질 수 있어요. 이 방의 점수는 대기실에서 볼 수 있어요"
- 도감의 다른 탭 숫자(증강·조합·보스·아이템)는 원래 규칙과 무관한 고정값이라 그대로.
- 대기실: 규칙 요약 근처에 [이 방 점수표] 버튼. 누르면 그 방 규칙으로 만든 `scoreTable`을 작은 창으로 보여 준다. 방장이 규칙을 바꾸면 열려 있는 창도 바로 바뀐다.
- 게임 방법 슬라이드는 이번에 바꾸지 않는다(방 안에서는 그 방 숫자, 밖에서는 기본 규칙 숫자를 이미 보여 줌).

## 6. 주고받는 이벤트 (`shared/src/protocol.ts`)

- 서버 → 화면: `tutorial:step`은 그대로(단계·진행 수·완료). 새 `tutorial:beat { step, beat, kind: 'focus' | 'card' | 'free', accept?: 'circle' | 'empty', circleId?: number, target?: 'me' | 'bot' }`. `beat`는 화면이 문구를 찾는 id(예: `own.mine`, `steal.counter`).
- 화면 → 서버: `tutorial:next`.

## 7. 테스트 (`shared/test/tutorial.test.ts`)

- 단계 순서 own → combo → steal → fever → zones
- `focus` 중 짚은 원이 아닌 곳을 누르면 점수·콤보·게이지·원 목록이 그대로, 짚은 원을 누르면 잡히고 다시 움직임
- `accept: 'empty'` 중 원을 누르면 무시, 빈 곳을 누르면 콤보 0
- `card` 중 판 클릭 무시, `tutorial:next`로 넘어감. 튜토리얼이 아닌 방의 `tutorial:next`는 무시
- 멈춘 동안 원 위치·피버 끝 시각·표적 끝 시각이 멈춤 시간만큼 밀림
- 봇 견제 장면에서 내 콤보가 끊기고 봇이 표적이 됨, 이어서 봇 색 원을 잡으면 반격 점수
- 피버가 켜지는 순간 카드 장면, 카드 동안 피버 시간이 줄지 않음
- 다시 접속하면 지금 장면을 다시 받음
- 도감 규칙 탭이 방 규칙(예: 파티 피버 ×5)과 상관없이 기본 규칙 숫자를 보여 줌. 화면 코드는 `guide.test.ts`처럼 `shared/test`에서 `client/src`를 불러 시험하므로, 규칙 탭 HTML을 만드는 함수를 DOM 없이 내보내 같은 방식으로 확인한다

화면은 빌드 뒤 로컬 미리보기에서 다섯 단계를 끝까지 해 보고, 멈춤 장면에서 빈 곳·다른 원을 눌러 아무 일도 없는지, Esc 나가기, 대기실 점수표가 규칙 변경에 따라 바뀌는지 확인한다.

## 내가 정한 것 (사용자 확인 필요)

- 추가한 기초: ⑤ 점수 구역, ②의 빈 곳 클릭(직접 해 봄), ③의 반격.
- (사용자 결정) ① 원은 하나씩 짚고 설명, 자유 연습 없음. ② 콤보 9에서 시작해 한 번 잡아 10을 만들고 점수 차이 설명. ④ 피버 설명 → 게이지 99% → 원 하나로 피버 진입 → 피버 상태 설명 → 피버 중 실습.
- ⑤ 자유 연습 목표 3개.
- ③에서 봇이 견제하는 때: 내 표적 시간이 끝난 직후(표적이 겹치면 누가 표적인지 헷갈림).
- 무지개 원·보스·아이템·레이저는 넣지 않는다(방 규칙에 따라 켜지고 꺼지므로 게임 방법 '심화'가 맡음).
- 멈춤 상태를 일시정지와 따로 둔다.

## 하지 않는 것

- 완료 여부 저장, 처음 접속 때 자동 시작
- 튜토리얼 문구에 점수·배율 숫자
- 게임 방법 슬라이드 내용 바꾸기
- 실패·시간 제한

## 이러면 실패 (기술적으로 돌아가도)

- 멈춘 장면에서 잘못 누른 클릭이 콤보를 끊거나 점수·게이지를 바꿈
- 튜토리얼이나 도감이 특정 규칙에서만 맞는 배율 숫자를 보여 줌
- 멈춤이 풀릴 때 일시정지 화면이나 카운트다운이 끼어들어 흐름이 끊김
